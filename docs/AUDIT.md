## 2026-10-05 — security pass after background jobs, snapshots and the hard refresh

### Fixed
- **Cross-site GET started real work** · the CSRF check skipped every GET, but `/api/bills`, `/api/stats`, `/api/court-cases`… scrape on GET (bills spends a captcha). A page in another tab (or another localhost port) could fire them with `<img>` / `fetch(no-cors)`. Now every method must be same-origin / `none`; verified in a real browser (8 forged requests from `localhost:4000` and `127.0.0.1:4000` refused, none scraped, normal use refused 0). `security.ts` `crossSiteReason`.
- **Rate limit key was caller-controlled** · `X-Forwarded-For` was believed on a loopback app, so a rotating header gave every request a fresh budget (and grew the bucket map). Ignored unless `APP_TRUST_PROXY=1`; spent buckets are swept.
- **Token compared with `===`** · now constant-time (`safeEqual`).
- **No trace of refused / privileged calls** · new event log + Settings › Xavfsizlik + `[security]` log lines.
- **Update route**: a failed pull after the auto-stash left the operator's local changes hidden in the stash (pop only ran on success); a diverged `main` was merged by plain `git pull`; two clicks ran two stash/pull/pop sequences; git could wait on a credential prompt. Now `--ff-only`, single-flight, `GIT_TERMINAL_PROMPT=0`, stash restored on every path. Tested against real throw-away repos.
- **Worker SSRF by DNS** · a worker URL was only checked by NAME; `127.0.0.1.nip.io` or an A record to `10.x` / cloud metadata passed. Now the resolved addresses must all be public (add and test); the test fetch no longer follows redirects.
- **`court-cases?detail=` unvalidated** · spliced into upstream URL paths and a curl argument (curl also expands `{}` / `[1-9999]` in URLs: a request multiplier). Shape-checked in the route and the lib; curl runs with `--globoff`.
- **Spreadsheet exports** · sent `Access-Control-Allow-Origin: *` on private data and put request values into the download filename unsanitized. CORS header removed, names restricted to `[A-Za-z0-9._-]`.
- **Dependencies** · `bun.lock` was stale (listed ~50 removed packages: 94 advisories). Regenerated; `postcss` / `nanoid` / `baseline-browser-mapping` overridden to patched versions; `bun audit --prod` = 0. Verified in a clean copy with a frozen-lockfile install (typecheck, lint, 445 tests). Extra `Permissions-Policy` locks and `Origin-Agent-Cluster`.

### Checked and fine
No TLS verification bypass anywhere · no `innerHTML` / `dangerouslySetInnerHTML` / `eval` (print windows escape scraped text) · `child_process` only `spawn`/`execFile` without a shell, constant git arguments · spreadsheet cells are typed strings (no formula injection) · snapshot file names are 9-digit STIR only · no secrets in the last 50 commits (pattern scan) · every route is `guard()`-wrapped (test).

### Deferred
- Remaining `bun audit` entries are eslint/babel build tooling (ReDoS on trusted files).
- Showing the incoming commits before «Yangilash» applies them (the update still trusts whatever is on `origin/main`, by design); `workers.json` tracked in git (removing it from the index would delete the operator's copy on their next pull).

## 2026-09-30 — full audit (security, reliability, dependencies, UI/a11y)

### Fixed
- **Dependencies** · `bun audit`: 93 advisories (3 critical, 49 high). 50 of 68 direct dependencies were never imported (scaffold leftovers: `next-auth`, `next-intl`, `recharts`, 30 Radix packages…). Removed → 18 left; with `next` 16.3.7 the audit reports **0 vulnerabilities** (verified in a clean copy: typecheck, lint, 330 tests, browser flow). `bun.lock` is regenerated by the next `bun install`.
- **Next.js critical advisories** (RCE on Windows hosts, image-optimizer RCE, middleware bypass) · `next` ^16.1.1 (locked 16.1.3) → ^16.3.7. `agentRules:false` stops Next 16.3 from rewriting AGENTS.md on `next dev`.
- **Data-loss risk** · `registry.ts writeStore` swallowed quota errors: the watchlist (only copy) could silently stop saving once caches filled localStorage. Now: evict response caches → drop case lists of non-watched companies → toast `sud:storage-full`. `cache.ts setCached` evicts oldest instead of failing. Tests: `lib/__tests__/storage-quota.test.ts`.
- **Body size** · no request-size limit → 8 MB cap in `guard()` (413).
- **Error leakage** · 500 responses returned raw `error.message` → generic in production.
- **Accessibility (axe, 3 widths, light+dark)** · text colour `--text-3` was 2.3:1 (170 nodes) → 4.5:1; dark KPI label 4.2 → AA; no `<main>` landmark → `<main id=main>` + skip link; two unlabeled `<nav>` → labelled; pie `role=img` containing buttons (nested-interactive) → `role=group`; company page had no `<h1>` → context bar name is `h1`; settings card titles jumped h1→h3 → `h2`.
- (Earlier this session, same audit theme) unguarded `DELETE /settings/workers`, CSRF/DNS-rebinding guard, LAN bind, SSRF on worker URLs — see SECURITY.md.

### Checked and fine
No horizontal overflow at 1440/700/375 on launcher, Kuzatuv, settings (4 tabs), documents, company overview/cases/profile, case drawer · no console errors/warnings · every icon-only button has an accessible name · every scraped string reaches printed HTML through `escapeHtml` · `.docx` fill escapes XML · `child_process` only via `execFile`/`spawn` without a shell · PDF/template/file ids are allow-listed · `execFile git` arguments are constants.

### Deferred (owner decision or larger)
- **CSP `script-src 'unsafe-inline'`** in production (Next's inline bootstrap). Fixing needs per-request nonces (middleware + dynamic rendering). Risk is low: no external origins, no user HTML rendered.
- **Update route runs `git pull origin main` + restart** (by design, privileged). A compromised GitHub account would be code execution on the operator's machine. Option: require signed commits / show the diff before applying.
- **`workers.json` is tracked in git** (private worker URLs). Move to `.gitignore` + `git rm --cached` if the repo is or may become public.
- **`NEXT_PUBLIC_APP_API_TOKEN`** is embedded in the browser bundle (protects against other machines/pages, not the person at the keyboard).
- **Rate limiter trusts `X-Forwarded-For`**; irrelevant on loopback, wrong behind a proxy.
- **Test gaps** (no unit tests): `lib/court-case.ts` (843 lines, curl/worker racing, parsing), `lib/stats.ts` aggregation, `lib/orginfo.ts` parsers (fetch path is tested), `sources/index.ts`, `lib/billing.ts` beyond the search path, all UI components (covered only by ad-hoc Playwright runs — no committed e2e suite).
- **Large files** worth splitting when next touched: `settings-view.tsx` (862), `court-case.ts` (843), `proto/primitives.tsx` (806), `sections/cases.tsx` (792), `billing.ts` (790).
- **Repo hygiene**: `mini-services/` (tor-manager, ihamkor-scraper incl. `downloaded_files/*.lock`) and root `worklog.md`, `README-DELIVERY.md`, `P0-RUNBOOK.md` look like leftovers; confirm before deleting.
- **Duplicated enrichment** (`lib/enrich.ts` vs the copy inside `views/watchlist.tsx`) — the source of two bugs already; merge into one function (see MAP.md §3).
- **Contrast of disabled controls** (e.g. the disabled «Ochish» button) is intentionally low (WCAG exempts disabled controls).
